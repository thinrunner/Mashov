# Mashov Hub — спецификация для Claude Code

Личная надстройка над משו"ב для двух детей в двух разных школах: регулярная синхронизация данных, удобный веб-интерфейс (мобильный и десктоп), мгновенные уведомления в Telegram. Только для семьи. Приоритеты: **безопасность → надёжность → удобство**.

---

## 0. Исходные условия и допущения

| # | Факт / допущение | Статус |
|---|---|---|
| 1 | Публичного API у Машов нет. Используется внутренний JSON API веб-версии (`https://web.mashov.info/api/`, иногда `https://mobileapi.mashov.info/api/`). Его уже разобрали open-source библиотеки: `pymashov` (Python, async, httpx), `mashov-api` (npm), интеграция `NirBY/ha-mashov` для Home Assistant. | Факт |
| 2 | API может измениться без предупреждения. Система должна это обнаруживать и сообщать, а не молча ломаться. | Требование |
| 3 | Два ребёнка — две школы, значит **два аккаунта Машов** (разные `semel`). | Допущение, проверить в Phase 0 |
| 4 | Вход по SMS/OTP **несовместим с «работает безотказно»**: каждое истечение сессии требует вашего участия. Целевой режим — **логин и пароль Машов** для каждой школы. SMS-режим остаётся только как временный и запасной. | Решение |
| 5 | Канал уведомлений — **Telegram**. WhatsApp требует Business API Meta: верификацию бизнеса, шаблоны сообщений, оплату за сообщение — для личного инструмента избыточно. | Решение |
| 6 | Интерфейс на русском; содержимое из Машов (предметы, комментарии учителей) на иврите, отображается с `dir="auto"`. | Допущение |
| 7 | Доступ: вы и, возможно, супруга. Доступ определяется устройствами в tailnet + passkey. | Допущение |
| 8 | Хостинг: **локально на Mac владельца**, без затрат. Домашний израильский IP снижает риск гео-блокировок. Цена решения: синхронизация и уведомления работают, только пока Mac включён, не спит и в сети. Архитектура переносима — позже переезд на облачную VM без переписывания. | Решение |
| 9 | Доступ с телефона вне дома — через **Tailscale** (бесплатный персональный план): приложение на Mac и телефоне, сервис не выставлен в интернет вообще. | Решение |

**Правовой статус:** личное использование своих учётных данных для доступа к данным своих детей. Неофициальный доступ формально может противоречить ToS Машов, поэтому нагрузка минимальная, никакого распространения и продукта.

## 1. Архитектура

```
[Телефон / ноутбук] ──Tailscale (WireGuard, приватная сеть)──┐
                                                               │ https://<mac>.<tailnet>.ts.net (tailscale serve, TLS)
                    ┌──────────── Mac (OrbStack / Docker) ─────┴──┐
                    │  app      FastAPI + статический PWA         │
                    │           слушает только 127.0.0.1           │
                    │  worker   планировщик синхронизации         │
                    │  bot      Telegram-бот (long polling)       │
                    │  SQLite (WAL) в ~/MashovHub/data            │
                    └──────────────┬──────────────────────────────┘
                                   │ только исходящие HTTPS
                    web.mashov.info · api.telegram.org · healthchecks.io
```

**Рантайм на Mac:** OrbStack (бесплатен для личного использования, легче Docker Desktop) + `docker compose`. Автозапуск: OrbStack стартует при логине, у контейнеров `restart: unless-stopped`. Telegram-бот работает через long polling — входящие соединения не нужны.

**Сон Mac:**
- Mac mini / iMac: Настройки → Энергосбережение → «Не переводить в сон автоматически», «Пробуждение для доступа к сети», «Автоматический запуск после сбоя питания».
- MacBook: при закрытой крышке без питания и монитора засыпает — синхронизация останавливается. Скрипт `scripts/keep-awake.sh` (обёртка `caffeinate -s`, работает только от сети) как launchd-агент. Ограничение явно принимается.
- Пропуски из-за сна не теряют данные: при пробуждении worker сразу делает полный цикл, все пропущенные события приходят пакетом с пометкой «пока Mac спал».

**Стек**
- Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2 + SQLite (WAL), APScheduler, httpx, python-telegram-bot.
- Клиент Машов: сначала оценить `pymashov`; если он неполный или нестабильный — собственный тонкий клиент на httpx за интерфейсом `MashovClient`, чтобы источник можно было заменить без изменения остального кода.
- Фронтенд: React + Vite + TypeScript + Tailwind, PWA (manifest + service worker, установка на домашний экран), без SSR.
- Все зависимости зафиксированы (lock-файлы), образы собираются из pinned base images.

## 2. Phase 0 — технический спайк (выполнить первым, это gate)

Цель: подтвердить на ваших реальных аккаунтах, что всё нужное доступно. **Без этого не строим остальное.**

1. Вход в оба аккаунта: (a) логин и пароль, (b) поток SMS-OTP — понять, какие запросы он делает и можно ли передать код через API.
2. Получить и сохранить сырые JSON-ответы всех эндпоинтов для обоих детей: оценки, поведение/посещаемость, домашние задания, расписание и его изменения, недельный план, история уроков, сообщения (inbox), уведомления Машов, праздники.
3. Измерить **время жизни сессии** и поведение при истечении (код ответа, тело).
4. Проверить, видит ли родительский аккаунт ребёнка сразу через `students` или требует отдельного выбора.
5. Результат: `docs/api-findings.md` — список эндпоинтов, примеры ответов (**с замаскированными персональными данными**), время жизни сессии, ограничения. И Pydantic-модели для каждого ответа.

**Критерий go/no-go:** логин и пароль работают стабильно, а оценки, поведение, домашка, расписание и сообщения доступны. Если работает только SMS-вход — остановиться и согласовать с владельцем режим работы.

## 3. Синхронизация (worker)

**Расписание**
- Учебные дни 07:00–22:00 — каждые 15 минут, со случайным разбросом ±3 мин.
- Ночью, в выходные и праздники — раз в 2 часа.
- Кнопка «Обновить сейчас» в UI (не чаще 1 раза в минуту).
- Строго последовательные запросы, пауза между ними, никакой параллельной долбёжки API.

**Пайплайн для каждого аккаунта**
1. Получить или переиспользовать сессию. При 401/403 — один повторный логин; при неудаче — статус `auth_failed` и алерт.
2. Для каждого эндпоинта: запрос → валидация Pydantic → нормализация → upsert.
3. **Изоляция ошибок:** поломка одного эндпоинта не останавливает остальные. Ошибка валидации сохраняет сырой ответ в `raw_failures` и отправляет алерт «изменился формат: <эндпоинт>».
4. **Diff:** у каждой нормализованной записи стабильный `natural_key` и `content_hash`. Новая запись или изменённый хэш создают строку в `events`.
5. Сырые ответы хранятся 30 дней (для отладки), затем удаляются.
6. После успешного цикла — пинг healthchecks.io (dead-man switch: если пинга нет 45 минут в учебное время, приходит алерт извне).

**Первый запуск** импортирует историю текущего учебного года **без** отправки уведомлений.

## 4. Модель данных (SQLite)

- `accounts` (id, label, semel, year, username, `password_enc`, auth_mode `password|sms`, session_enc, session_expires_at, status, last_success_at, last_error)
- `children` (id, account_id, mashov_student_id, display_name, class, school_name, color)
- `grades` (child_id, natural_key, subject, title, type, date, grade, raw_grade_text, teacher, content_hash, first_seen_at)
- `behavior` (child_id, natural_key, date, lesson_no, subject, type — опоздание/отсутствие/замечание/похвала, justified, comment, teacher, content_hash, first_seen_at)
- `homework` (child_id, natural_key, subject, lesson_date, due_date, text, done_by_parent_flag, content_hash, first_seen_at)
- `timetable` (child_id, weekday, lesson_no, start, end, subject, teacher, room) + `timetable_changes` (date, lesson_no, kind — отмена/замена/перенос, details)
- `messages` (child_id|account_id, natural_key, sender, subject, body, sent_at, has_attachments, read_in_app)
- `events` (id, child_id, kind, ref_table, ref_id, created_at, notified_at, seen_at, severity)
- `notification_prefs` (kind × child × channel: instant | digest | off) + quiet hours
- `sync_runs` (account_id, started_at, finished_at, status, per_endpoint_status JSON)
- `raw_snapshots`, `raw_failures` (TTL 30 дней)

## 5. Уведомления (Telegram)

**Мгновенно** (в тихие часы 22:00–07:00 откладываются в утренний пакет):
- Отсутствие, опоздание, дисциплинарное замечание — severity high.
- Новая оценка (с оценкой и предметом; ниже порога — пометка ⚠️, порог настраивается, по умолчанию 70).
- Новое сообщение от учителя или школы (отправитель, тема, первые 200 символов).
- Изменение расписания на сегодня или завтра (отмена, замена).

**Ежедневный дайджест, 19:00:** для каждого ребёнка — завтрашнее расписание с изменениями, домашка на завтра, всё новое за день, если не было мгновенных уведомлений.

**Пятничный итог недели:** оценки за неделю, посещаемость, открытая домашка.

**Служебные алерты** (отдельно и заметно): `auth_failed`, «изменился формат API», «синхронизация не проходит более 1 часа», бэкап не выполнился.

**Правила:**
- Каждое сообщение начинается с имени ребёнка и его цвета-эмодзи, чтобы сразу было видно, о ком речь.
- Кнопка «Открыть» ведёт deep link на запись в веб-интерфейсе.
- Дедупликация по `events.id`; одно событие — одно уведомление.
- Бот отвечает только на `chat_id` из allowlist, всё остальное игнорирует.
- Команды бота: `/today`, `/tomorrow`, `/status`, `/sync`, `/code 123456` (ввод SMS-кода в SMS-режиме).

**SMS-режим (временный):** когда сессия истекла, бот пишет «Нужен код для <школа>». Вы отправляете `/code 123456` или вводите его в веб-интерфейсе; worker завершает логин и продолжает работу.

## 6. Веб-интерфейс (PWA)

Mobile-first, одинаково удобен на десктопе. Светлая и тёмная тема (системная по умолчанию). Быстрый: первая загрузка < 1.5 с на 4G; данные из локального API, без внешних CDN в рантайме.

**Экраны**
1. **Сегодня** (главный): карточка на каждого ребёнка — сегодняшние уроки с выделенными изменениями, новые события (непросмотренные сверху), домашка на завтра. Наверху индикатор «обновлено N мин назад» и статус обоих аккаунтов (зелёный / жёлтый / красный).
2. **Ребёнок** — вкладки:
   - **Лента:** хронология всех событий с фильтрами по типу и предмету.
   - **Оценки:** по предметам, среднее, тренд (sparkline), график за год, подсветка падений.
   - **Посещаемость и поведение:** счётчики за период, по предметам и дням недели — чтобы видеть закономерности («всегда опаздывает на первый урок по вторникам»).
   - **Домашка:** список по сроку, пометка «проверено родителем».
   - **Расписание:** неделя с изменениями.
   - **Сообщения:** входящие с полным текстом и вложениями.
3. **Поиск** по всем данным обоих детей.
4. **Настройки:** уведомления (тип × ребёнок × instant/digest/off), тихие часы, порог оценки, статус аккаунтов, ввод SMS-кода, кнопка «Обновить сейчас».

**UX-правила:** «Отметить всё просмотренным»; pull-to-refresh на мобильном; иврит в содержимом с `dir="auto"`; цвет каждого ребёнка используется последовательно во всём интерфейсе; пустые состояния понятные («Новых событий нет — всё спокойно»).

## 7. Безопасность

- **Периметр:** приложение слушает только `127.0.0.1`; наружу публикуется исключительно через `tailscale serve` внутри приватной tailnet. Никакого port forwarding на роутере, никаких публичных туннелей. Tailscale ACL: доступ только с устройств владельца (и супруги, если решено).
- **Второй слой:** вход в приложение по passkey (WebAuthn) — на случай, если устройство в tailnet окажется в чужих руках. Сессия 30 дней на доверенном устройстве.
- **Секреты:** пароли и сессии Машов, токен бота хранятся зашифрованными (Fernet / AES-GCM). Мастер-ключ — в **macOS Keychain**, передаётся в контейнеры при старте скриптом `scripts/start.sh`; не в репозитории, не в `.env`, не в БД.
- **Диск Mac:** FileVault должен быть включён (проверка в `scripts/doctor.sh`).
- **Данные детей:** логи без персональных данных (маскирование имён, ID, текста сообщений); никакой сторонней аналитики, трекеров и внешних шрифтов в рантайме; строгий CSP; `Referrer-Policy: no-referrer`.
- **Mac:** включён встроенный firewall macOS; `doctor.sh` проверяет FileVault, firewall, что порт приложения не слушает на внешних интерфейсах.
- **Репозиторий:** приватный в GitHub-аккаунте Gravion; `.env` и бэкапы в `.gitignore`; gitleaks в pre-commit; Dependabot.

## 8. Надёжность и эксплуатация

- `restart: unless-stopped` у всех контейнеров; healthcheck endpoints.
- **Бэкапы:** каждую ночь `sqlite3 .backup` → шифрование (age) → папка в iCloud Drive (хранение 30 дней) + Time Machine, если настроен. **Тест восстановления** — обязательная часть приёмки.
- **Мониторинг:** healthchecks.io (бесплатный план) как внешний dead-man switch: если Mac выключен, спит или без сети дольше 45 минут в учебное время, приходит письмо или Telegram-сообщение извне. Это единственный способ узнать о проблеме, когда сам Mac молчит.
- **Обновления кода:** `scripts/update.sh` (`git pull && docker compose up -d --build`); миграции БД через Alembic.
- **Переносимость:** весь стек — `docker compose` + одна папка данных; переезд на облачную VM позже = копирование папки + замена Tailscale serve на Cloudflare Tunnel/Access.
- **Деградация:** если Машов недоступен, UI показывает последние данные с явной пометкой «данные от HH:MM».

| Фаза | Объём | Приёмка |
|---|---|---|

## 10. Что нужно сделать владельцу до старта

1. Перевести **оба** аккаунта Машов на логин и пароль (в настройках Машов или через секретариат каждой школы). Записать `semel` обеих школ.
2. Создать Telegram-бота через @BotFather, получить токен; узнать свой `chat_id`.
3. Установить OrbStack и Tailscale на Mac, Tailscale на телефон (один аккаунт); включить HTTPS-сертификаты в настройках tailnet.
4. Настроить энергосбережение Mac (раздел 1) и проверить, что FileVault включён.
5. Решить, есть ли доступ у супруги (тогда её устройство тоже в tailnet).

## 11. Открытые вопросы
- Даёт ли родительский аккаунт доступ к тем же данным, что и аккаунт ученика (у некоторых школ часть модулей отключена)?
- Отличаются ли модули между двумя школами (например, одна не ведёт домашку в Машов)? UI должен корректно скрывать пустые разделы.
- Нужна ли позже пересылка уведомлений в WhatsApp (можно через уже существующий проект Telegram↔WhatsApp broker).
